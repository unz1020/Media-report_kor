# 소재 식별정보와 운영안 분리

## 관리 기준
- 기존 등록명, 보고서 파일명, 증빙 이미지, 실제 소재 파일과 성과 원본은 수정하거나 이름을 바꾸지 않는다.
- AE가 원본을 확인한 경우에만 소재ID와 버전을 등록한다. 자동 번호 발급, A/B 순서 추정, 파일명 유사도 연결은 하지 않는다.
- 식별 키는 소재ID+버전이다. 같은 소재를 여러 매체에서 사용하면 같은 키를 사용할 수 있으나 매체·지면별 성과 원본은 각각 확인 연결한다.
- 새 버전은 해당 버전의 별도 소재/증빙 기록에서 등록한다. 기존 증빙의 식별정보 수정은 그 증빙의 정정이며 자동 버전 이력 생성이 아니다.
- 서로 다른 버전의 원본명이 같고 명시적 원본 연결이 없거나, 한 성과 원본을 여러 버전이 주장하면 집계를 보류한다.
- ID/버전의 정의(관리명·규격·보고된 파일명)가 충돌하면 경고하고 성과 연결을 보류한다. ID는 파일 동일성을 입증한 해시가 아니다.

## 파일명
권장 예: `광고주_CR001_기획전_v01_30초.mp4`

이름은 미리보기일 뿐 실제 파일을 변경하지 않는다. 소재 규격 또는 확장자가 없으면 자리표시자를 보여준다. 보고된 소재 파일명은 AE 입력 정보이고, 증빙 보고서 파일명과 별개다. 기존 원본명은 별도로 유지한다.

## 저장과 조회
기존 save_creative_link 액션에 선택적인 materialIdentity 주석을 추가한다. 생략하면 기존 값 유지, null은 명시적 해제다. 원래의 권한·광고주/월·증빙 버전 CAS 검사를 유지하며 같은 증빙을 재수입할 때 생략된 주석을 보존한다. 식별정보를 해제해도 명시적 성과 연결을 지우지 않는다. 해제 후 기존 정확한 이름 기준 연결은 다시 적용될 수 있다.

CSV 기존 열은 그대로 두고 ID·버전·관리명·보고된 파일명·규격·연결 상태를 뒤에 추가한다.

## 운영안
기본 쇼룸은 성과 또는 증빙 자료가 연결된 항목이다. 자료의 존재는 현재 집행 중이라는 뜻이 아니다. 계획만 있는 항목은 운영안 포함 옵션으로 따로 접근한다. 원본 운영안은 삭제하지 않는다. 개요의 운영안 합계는 확정 예산이나 실제 집행액이 아님을 표시한다.

## 배포 순서와 범위
1. 코드/합성 테스트만 별도 승인 후 공개하고 CI 검증한다. 고객 파일·원본 JSON·이미지·로컬 fixture/API stubs는 공개하지 않는다.
2. 별도 승인 후 reporting-store 함수의 7개 파일을 배포한다. 신규 creative-material-input.ts를 포함한다. DB 마이그레이션과 환경변수/권한 변경은 없다.
3. 함수 검증 후 별도 승인 범위에 따라 PR 병합 및 프런트엔드 운영 배포를 진행한다. 실제 고객 소재ID·성과 연결·운영정보는 자동 입력하지 않는다.
