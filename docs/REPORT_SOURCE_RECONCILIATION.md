# 보고서 중복과 Addr.TV 분류

- 파일의 끝에 붙는 발행 날짜와 Final/최종 표기를 제거하고 공백·밑줄 차이를 정규화해 같은 보고서 계열을 찾는다. 광고주·캠페인 월·파일 본문의 캠페인명은 구분한다. 최신 기준일, 같은 날이면 마지막 수정 시각을 사용하며 이전 스냅샷은 남긴다.
- 다음 달 수신일 때문에 성과 기간이 미래 월로 지정된 기존 데이터는 성과 기준일의 월로 보정한다. 월 전체 조회는 최신 누적 표를 사용하고 부분 기간은 일별 데이터로 계산한다.
- Overall과 같은 매체의 상세 Total 표는 서로 다른 분해 방식이므로 한 번만 합산한다. 비용과 클릭 정의가 명확한 Overall을 누적 집계 기준으로 사용한다. 카카오 검색광고 Summary의 매체·캠페인·주차·키워드 표도 처음 전체 합계 한 개만 집계한다. 기존 저장 자료에도 읽을 때 동일한 정제를 적용한다.
- Gmail 성과 검색에 Addr.TV, Addressable, 어드레서블 제목을 포함한다. TV의 Summary는 누적 Data 아래 통신사별 Total만 읽는다. 주차·소재·채널·REACH를 추가 노출로 합산하지 않는다. 누적 표가 없는 파일은 검수 오류로 표시한다.
- 같은 메일의 TV 통합 보고서에 SKB/LGU+ RawData 파일의 일별 유효노출을 연결한다. 원본 2개는 보조자료로 표시하고 별도 성과 데이터셋으로 반영하지 않는다. 통신사별 일별 합계와 누적 노출이 다르면 반영을 막는다. 통합 보고서 없이 원본만 있는 경우 캠페인 집행요약을 읽는다.
- TV에 없는 클릭/CTR은 빈 값으로 유지한다. 통합 CTR의 분모에도 클릭 지표가 제공되는 자료의 노출만 사용한다. 일별 비용을 월간 비용에서 임의 배분하지 않는다.
- 회귀 검증: `node scripts/verify-report-sources.cjs`. 실 메일 첨부·실 광고 성과는 공개 저장소에 포함하지 않는다.
